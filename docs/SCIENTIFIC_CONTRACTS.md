# Scientific contracts

Current scope reviewed 27 September 2026 during P17. The P02-P06 sections below identify the original contracts, which are retained for reproducible replay. Later adapters do not silently change those earlier definitions. The capability audit in [P17_CAPABILITY_AUDIT.md](P17_CAPABILITY_AUDIT.md) distinguishes implemented behavior, internal numerical evidence and external validation still needed.

Model/legacy observation source: `science/contracts.py`, schema v1. P04 instruments: `science/instruments.py`, schema v2. Public API models derive from these Pydantic contracts; frontend runtime readers reject incompatible responses. The model catalogue is also schema v2; its version is separate from scientific-record versions.

| Contract | Meaning and required distinctions |
| --- | --- |
| `Variable` | Stable ID, original variable name/units, standard name, physical definition, decoded units and original packing/missing metadata. |
| `Coordinates` | Actual UTC timestamps, calendar and source time units; irregular positive-down metre depths; sorted latitude and longitude in [-180,180). Original coordinate values remain in source metadata. |
| `Provenance` | Provider, version, model/observation/derived/simulation kind, source/licence links, citation, retrieval time, file fingerprints, transformations and limitations. |
| `CaseManifest` | Verified subset bounds/time/depth coverage, analytical/display coordinates and methods, actual profile summaries, source records, samples and derived-file hashes. |
| `Observation` | Platform/cycle/time/location, mode and QC, source file fingerprint, raw/adjusted values/errors, selected fields, pressure and derived depth, source-order indices and explicit eligibility. |
| `OperationResult` | Source/case/variable, actual timestamp, shape, coordinates, units, representation, processing and manifest fingerprint. Flattened values are ordered depth then latitude then longitude; longitude changes fastest. |

Model arrays are scalar fields for temperature, salinity, eastward velocity and northward velocity. "Currents" in the workspace refers to the two source horizontal components. No vertical current or derived speed is silently substituted. Ocean values are not generated by a language model.

## Supported input

The P02 HYCOM-style NetCDF adapter supports independent one-dimensional `time`, `depth`, `lat`, `lon` coordinates and four compatible scalar fields on that shared grid. An explicit variable-name map can bind different source names with the same declared definitions. Dimension order may differ; the adapter reorders it. Coordinate sorting always reorders the data as well.

For this adapter, supported calendars are standard, Gregorian and proleptic Gregorian, using CF numeric time units. Depth must declare metres and a positive direction. Pressure/sigma coordinates, curvilinear or staggered grids, grid-relative currents, potential/conservative temperature and incompatible units are rejected. Unsigned reinterpretation is also rejected until separately implemented. This is a supported subset of CF interpretation, not an arbitrary NetCDF compatibility claim. The separate GODAS and GOBAI adapters below preserve their different temperature, salinity and pressure definitions.

Packed data are masked for fill/missing/declared valid ranges **before** decoding as `packed × scale_factor + add_offset` in float64. Source attributes are preserved. Existing in-range longitude floats are not altered unnecessarily. Source precision is not improved by the larger decoded dtype.

The legacy P02 Argo adapter supports bounded core-profile NetCDF. It remains unchanged for the pinned model manifest. The P04 observation adapter below adds per-parameter modes and genuine sensor examples through a separate contract.

## Instrument contract v2

`InstrumentSummary` carries stable source-derived identity, sensor type, platform, source time range, actual location, track, sample count, variable metadata and provenance. `InstrumentProfile` adds ordered `Measurement` rows, methods, source metadata and warnings. Each `Parameter` records its definition, units, original field, processing mode, QC scheme and accepted count. Each `Reading` retains selected/raw/adjusted values, their flags, supplied adjustment error and an eligibility reason. Missing readings remain null. Original pressure, derived depth, per-sample position/time and structured coordinate flags stay separate.

Argo R selects raw; A/D selects adjusted, with no raw fallback. BGC uses each parameter's processing mode and raw R BGC values are inspect-only. Argo 1/2, QARTOD 1, WOCE 2 and declared CSV 1/2 are distinct eligibility rules. Coordinate checks apply separately; unavailable source flags are blank, not invented. Depth uses GSW 3.6.20 `-z_from_p` with sea pressure in dbar and source latitude. P04 preserves rather than collocates sensor records.

Supported runtime formats are Argo/BGC NetCDF, documented IOOS glider row-NetCDF, original CTD Exchange and Depth Atlas CSV v1. The parser bounds each input to 2 MB/24 profiles/5,000 samples and output to 3.5 MB. Metadata/units errors return named 422 responses; resource limits return 413. The server reparses original bytes per request and does not persist user-uploaded content. Temporary imports remain in browser memory until clear/reload. Since P16C, explicit investigation saves retain the original bytes, mappings, parsed profiles, settings and results in IndexedDB on the user's device; portable JSON/ZIP exports contain those records. Replay sends the included original bytes back to the service for verification. P16E allows up to eight sequentially reviewed files, retaining the per-file limits and a 20,000-sample workspace ceiling plus profile/source/decoded-byte budgets. This is not an unlimited batch or server archive. See PHASE_16C_IMPORTED_REPLAY.md, PHASE_16E_CONTINUITY.md and the public observation import guide.

## Errors and resource limits

Unsupported science raises a named `UnsupportedData` error. API errors use `{error: {code, message, request_id}}`. Invalid inputs never return plausible substitute values.

- Unsupported time, depth, variable semantics, incomplete/outside bounds: HTTP 422.
- Unknown case/profile: HTTP 404.
- Core case-subset requests above 100,000 scalar values: HTTP 413 with smaller-request guidance. Wider-source, structure, import and replay workflows have their own explicit limits; this is not a universal limit for every operation.
- Failed packaged-data integrity: HTTP 503.
- Missing cell: valid result with JSON `null`, not an HTTP error and not zero.
- Offline model preparation: at most 12 million scalar values per input file; supported Argo files at most 500 profiles and 10,000 levels per profile.

No endpoint fetches a caller-supplied URL or opens a caller-supplied path. IDs resolve through the packaged catalogue. Cache capacity is explicit and does not grow with arbitrary requests.

The model/profile overlap record describes availability only. It must not be reused as an independent validation score, confidence estimate or a completed collocation result. Numerical comparisons separately retain their declared method, inputs, tolerances and evidence.


## P05 comparison and coverage contracts

`science/evidence_contracts.py` defines schema 1 comparisons and coverage, method `p05-native-column-v1`. Both carry identical matching settings and model/library fingerprints. Each comparison retains all original rows with source index, timestamp/coordinates, QC/mode, selected value, signed time offset, model column/distance, native bracket and interpolation weight, eligibility and one first-failed reason. Model and residual are null when a sample is excluded. Aggregate counts and sample metrics must agree with accepted rows.

Coverage includes exact accepted depths and accepted-sample time/distance ranges. For a zero-pair profile, source time offsets are diagnostic only and distances remain null. Minimum absolute accepted time offsets and suggested alternate offsets/distances support truthful ranking even for moving casts. The browser checks requested identities, arithmetic, units, timestamps, limits, metrics and count consistency before displaying results. Scientific definitions and gate order are specified in [PHASE_05_EVIDENCE.md](PHASE_05_EVIDENCE.md). The P02 model manifest remains unchanged.

P16C applies these same physical/QC gates to supported imported temperature and practical-salinity observations by reparsing the original file. Imported coverage describes that file only. Chlorophyll is inspectable and saveable as an observation, with no supplied model chlorophyll field or chlorophyll residual. P16D adds exact native-cell observation-support association and sensitivity, without turning sample coverage into a probability or confidence estimate. Historical saved results retain their original method/caveat text; obsolete capability wording in a frozen record does not define the current import workflow.


## P06 exchange and derived products

The CF-1.10 exchange uses native float64 fields and coordinates, positive-down metre depths, and proleptic Gregorian time. Practical salinity is explicitly dimensionless with the original psu metadata retained. Horizontal kinetic energy is `(u*u + v*v)/2`, in square metres per square second, calculated before display reduction. It uses the joint finite mask, excludes vertical velocity, and is not eddy kinetic energy. Operation results identify it as `kind: derived` and include method `horizontal-ke-v1`.

`/api/products` lists installed product metadata. `/api/data-access` describes the exchange artifact, registered adapters, supported protocols and actual availability. `/data/bay-bengal-2024-01.nc` and `/data/manifest.json` are public CDN assets on Vercel and file responses locally. The existing source case manifest is unchanged.

THREDDS WMS/WCS responses have a tested 0.0001-degree horizontal-coordinate tolerance; WCS maximum tested longitude regularization was 0.0000826928 degree. Exact-coordinate consumers should use DAP or the native file. Source/protocol numerical checks use 1e-12 absolute tolerance and identical missing masks. This is scoped interpretation and interoperability, not universal CF/OGC certification. See PHASE_06_STANDARDS.md and deploy/standards/README.md.

Registrations contain trusted maintainer code. Core adapters return the normalized ModelGrid; derived products declare dependencies, units, definition, versioned method and limitations. External ML metadata additionally requires model, training-data and validation references. Uploaded files cannot install code. The core derived-product registry supplies horizontal kinetic energy; P15 separately integrates the existing GOBAI-O2 ML-derived source in the Regions workspace. This app does not train that model.

## Later historical-source and laboratory contracts

- The three HYCOM workspace cases preserve 40 native depth levels from 0 to 5,000 m, with missing wet/land/deep cells retained. They cover bounded January 2024 Bay of Bengal/Arabian Sea and March 2024 Bay of Bengal windows. Source depths do not guarantee a value at every location or depth.
- The three Pacific GODAS workspace cases use SON 2013, 2015 and 2022 monthly potential temperature, with 28 native levels from 5 to 459 m. Climate anomalies use a complete 1991-2020 matching-calendar-month baseline and explicitly equal-weight monthly SON means. This is not instantaneous in-situ temperature or a new climate simulation.
- Wider GODAS access covers pinned September/October 2022 potential temperature and source salinity in g/kg. The latter is not relabelled practical salinity or TEOS-10 Absolute Salinity. GOBAI-O2 v2.2, NCEI archive 4.4, retains original oxygen, separate producer uncertainty and pressure coordinates from 2.5 to 1,975 dbar. Missing uncertainty is not filled from oxygen. See PHASE_15_WIDER_COVERAGE.md.
- Drift uses historical horizontal currents at fixed selected native depths for passive tracers. It does not model sinking pebbles, wind-driven objects or search-and-rescue probabilities. Heat & Depth separates historical surface-event detection from linked native profiles and explicitly named density, stratification and column potential-enthalpy diagnostics.
- Feature evolution measures correspondence between threshold-defined native regions. It does not establish the identity or path of water parcels. Blackout excludes observations from evidence while leaving the original model and assimilation unchanged. The expedition experiment evaluates historical model sampling/reconstruction, not forecast improvement.
- P16 explanations use current structured results and cited method descriptions. The provider-free assistant works; an optional external LLM is unconfigured. Numerical regressions and source checks do not substitute for independent oceanographic review or an actual unfamiliar-user study.
